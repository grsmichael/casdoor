## tools/nav 服务导航容器化

把 `tools/nav`（零依赖 Python 导航服务）也做成容器，与 casdoor 一起调试。

- 新增 `tools/nav/Dockerfile`（python:3.12-alpine + docker-cli + curl）
- 新增 `tools/nav/docker-compose.yml`，容器名 `casdoor-nav`，端口 8899
  - 只读挂载 `/var/run/docker.sock`，让容器内 `docker ps` 能查容器状态（仅展示）
  - `extra_hosts: host.docker.internal:host-gateway`，Linux/Docker Desktop 通用
- 改造 `serve_nav.py`，新增环境变量：`NAV_PROBE_HOST` / `NAV_HOST_IP` / `NAV_PORT` / `NAV_BIND`
  - **关键**：容器内 `127.0.0.1` 是容器自己，探测目标必须指到宿主机，否则服务全误报 down
  - `host_ip_for_share()` 让页面分享地址显示宿主机 IP 而非容器 IP

### 踩坑

- `docker compose build` 在本机报 `failed to update builder last activity time: ... operation not permitted`（沙箱限制 buildx 写 `~/.docker/buildx/activity`）
  - 绕开：`DOCKER_BUILDKIT=0 docker build ...`，再用 `compose up -d --no-build`
- services.json 里容器名写的是 `casdoor-casdoor-1` / `casdoor-db-1`（仓库根 compose 的命名），
  与本次 `docker run` 起的 `casdoor-test` 对不上，故容器状态栏显示「容器不存在」——非 bug，改名即可

## 采用 addyosmani/agent-skills 规范（全量安装 25 个 skills）

用户要求项目按 <https://github.com/addyosmani/agent-skills> 落地，选择「全量安装」。

- 安装位置：项目级 `.workbuddy-ai/`
  - `skills/` 25 个（24 生命周期 skill + `using-agent-skills` 元技能）
  - `agents/` 4 个人格（code-reviewer / test-engineer / security-auditor / web-performance-auditor）
  - `references/` 7 份共享检查清单
- **关键：相对引用路径**。skill 内用 `../../references/x.md` 引用仓库级清单，
  故 `references/` 必须放在 `.workbuddy-ai/` 下（与 `skills/` 同级），
  这样 `skills/<name>/SKILL.md` 的 `../../` 才能解析到它。skill 自有清单用 `references/x.md`。
- 校验：25/25 frontmatter 合规（name + description），仓库级与自有 references 均无断链
- `CLAUDE.md` 追加「Agent skills」一节，声明生命周期 DEFINE→PLAN→BUILD→VERIFY→REVIEW→SHIP，
  并明确**冲突优先级：本项目 CLAUDE.md 的约定 > 通用 skill 默认行为**
  （例：TDD skill 主张写测试，但本项目「不主动加 Go test」优先）

### 踩坑

- `git clone https://github.com/...` 走沙箱代理报 `CONNECT tunnel failed, 502`
  **可用替代**：`curl -L https://codeload.github.com/OWNER/REPO/tar.gz/refs/heads/main`（实测 200）
- 校验脚本正则坑：`(?<!\.)references/` 挡不住 `../../references/`（前一个是 `/` 不是 `.`），
  会产生大量误报。正确写法 `(?<![/\w.-])references/`
