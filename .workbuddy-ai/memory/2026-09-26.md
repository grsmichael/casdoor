  并明确**冲突优先级：本项目 CLAUDE.md 的约定 > 通用 skill 默认行为**
  （例：TDD skill 主张写测试，但本项目「不主动加 Go test」优先）

- `git clone https://github.com/...` 走沙箱代理报 `CONNECT tunnel failed, 502`

## 全量 Docker 启动（docker-compose.full.yml）

新建 `docker-compose.full.yml`，一次起齐 services.json 登记的 6 个服务。
（`docker compose -f docker-compose.full.yml up -d db casdoor` 先起核心，再 `up -d` 起前端）

结果：8000/7001/7002/3306/389 全 up，1812 UDP 恒灰（脚本不探测，符合设计）；
容器状态栏也对上了（casdoor-casdoor-1 / casdoor-db-1 与 services.json 的 container 字段一致）。

### 关键技术点（都是踩过才发现的）

1. **数据源不能用 localhost**。`conf/conf.go:96` 在 `RUNNING_IN_DOCKER=true` 时把 localhost
   重写成 `172.17.0.1`（linux 分支），compose 自定义网络里未必可达。
   **解法**：`conf.go:44 GetConfigString` 是**环境变量优先于 app.conf**，
   直接传 `dataSourceName=root:123456@tcp(db:3306)/`，用 compose 服务名，稳。
2. **web-old 的代理改不了**。`web-old/craco.config.js` 把 devServer proxy 硬编码
   `http://localhost:8000`，而 CLAUDE.md 规定 web-old 只读。
   **解法**：`network_mode: "service:casdoor"` 共享网络命名空间，localhost:8000 就真是 casdoor。
   代价：7002 的端口映射只能写在 casdoor 服务的 ports 里。
3. **web-old 端口钉死在 7001**。它的 `yarn start` 是 `cross-env PORT=7001 craco start`，
   cross-env 会覆盖外部 PORT，与 web 撞车。
   **解法**：绕过 script，直接 `PORT=7002 HOST=0.0.0.0 ./node_modules/.bin/craco start`。
4. **MySQL 数据卷别用官方的 `/usr/local/docker/mysql`** —— 不在 Docker Desktop 默认文件共享
   列表内，macOS 上挂载失败。改用命名卷 `mysql-data`。
5. **frontend dev server 必须绑 0.0.0.0**（vite `--host 0.0.0.0`，CRA `HOST=0.0.0.0`），
   否则容器外访问不到。web 的后端代理走 `CASDOOR_BACKEND=http://casdoor:8000`。
6. web 用 vite 5 + react-scripts 5(webpack 5)，node:20 无 OpenSSL 兼容问题，不需要 legacy provider。
